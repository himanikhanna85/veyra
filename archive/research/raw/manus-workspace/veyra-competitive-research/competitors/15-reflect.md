# Reflect (SmartBear) — competitor profile

**Research date: 6 October 2026.** This is a public-source desk review, not a hands-on benchmark. Claims are labelled as **vendor-marketed**, **documented capability**, **independently supported**, or **assessment/inference**. “Unique” is used only for distinctive positioning; no exclusivity is inferred.

## 1. Active identity, ownership, availability, and intended customer

Reflect is currently marketed as **SmartBear Reflect**, an agentic/no-code test automation product for web and mobile applications. SmartBear’s live product page offers a free trial, a sales contact path, and links to SmartBear support documentation; this is strong public evidence that the product is actively available as of the research date [1]. SmartBear announced its acquisition of Reflect on 25 January 2024. The announcement identifies Reflect as an AI-powered no-code web-application testing platform and says it joined SmartBear’s integrated-hubs strategy [2]. Therefore the current owner is SmartBear; the former Reflect startup should not be treated as an independent vendor. The old `reflect.run` identity remains visible in documentation, API endpoints and signup links, but current product merchandising is under SmartBear.

The intended customer is a functional QA team, manual tester, developer, or development/testing organization that wants cloud E2E automation without building and maintaining Selenium-style frameworks. SmartBear explicitly contrasts automation engineers spending months on frameworks with “functional testers” building regression tests without setup [1] (**vendor-marketed positioning**). The current scope is much broader than a browser-only V0: the product page advertises web, native real-device mobile, API, visual, email/SMS, data-driven, CI/CD, scheduling and cross-browser testing [1] (**vendor-marketed; individual features are documented in the linked product documentation**). A TestGuild catalog independently describes Reflect as a paid, cloud-based no-code/AI test-automation product for small teams and lists web/mobile/API/visual, CI/CD, data-driven, self-healing, and diagnostic features [3], but its page contains no reviewer ratings and should be treated as corroboration rather than a performance benchmark.

## 2. Distinctive capabilities and mechanism versus the category baseline

The distinctive mechanism is a hybrid of recorder-generated steps, free-form natural-language AI prompt steps, and AI fallback for locator resolution. Reflect’s documentation says a prompt can represent one action, multiple actions, an assertion, or a question; at runtime Reflect consults an LLM to inspect the page and determine actions [4] (**documented capability**). This is more expressive than a conventional recorder constrained to a fixed action vocabulary, while still retaining a visual step editor. SmartBear says recorded selectors are attempted first and its AI Assistant uses expected text plus the editable step description when selectors fail [4] (**documented capability; “resilient” and maintenance reduction are vendor claims**). This is a distinctive implementation of self-healing, not proof that all repairs are correct.

Reflect’s test oracle model is relatively mature for a no-code browser product. Documented assertions include exact string, arithmetic formula, numeric range, membership in a list, non-empty checks, variable matching, and Boolean AI assertions. AI prompts can also answer arbitrary questions, although a question has no assertion by default until the user adds one [4][5] (**documented capability**). This supports explicit checks rather than relying only on “the click completed,” and is relevant to Veyra’s evidence-backed PASS/FAIL thesis. However, the docs do not establish a business-semantic contract layer that connects an assertion to approved business rules, domain entities, risk, or a durable application behaviour model (**unverified; absence of public documentation is not proof of absence**).

Reflect has reusable composition. A named Segment is a reusable sequence of steps; changes propagate to dependent tests, and Segments can receive Parameters. The documented limitation is that Segments cannot reference other Segments, so nesting is not supported [6] (**documented capability and limitation**). Variables can be extracted from page text or inputs; Parameters are values passed into a test; dynamic generators include random strings, numbers, timestamps and dates. Segments can be parameterized for common flows such as login and search [5] (**documented capability**). This is close to reusable modules, but the public model is workflow-step reuse rather than Veyra’s proposed semantic business modules with typed inputs/outputs, preconditions/postconditions, approved rules and dependency graphs (**assessment**).

Data-driven execution is documented through Variables, Parameters and account-level secrets. Secrets are encrypted separately and decrypted only at runtime for use in tests [5] (**documented capability**). The pricing page says test cases and users are unlimited across Premium, Advanced and Enterprise, while execution is metered through monthly Credits [7] (**official pricing terms**). Reflect also supports API steps inside web tests and standalone API tests, although that capability is outside Veyra V0’s deliberate scope [1][7] (**documented capability**).

Diagnostics are a clear category strength: SmartBear says each test run includes HD video, synchronized English-language steps, JavaScript console logs and network logs; it also advertises complete repro steps and evidence for failures [1][7] (**vendor-marketed and pricing-page documentation**). Reflect exposes suites and a Developer API, and its CI/CD documentation shows remote execution triggered by API calls from Azure Pipelines, Bitbucket, CircleCI, GitHub Actions, GitLab, Jenkins and other systems [8] (**documented capability**). The public pages support historical run lists and suite execution, but I found no documented “historical defect memory,” failure-cluster learning, coverage-risk graph, or ABM-like graph linking intent, state, dependencies and approved rules (**unverified**).

## 3. Current pricing, free trial, quotas, and units

SmartBear’s official pricing page currently lists a **14-day free trial with unlimited functionality** [7]. It presents three tiers—**Premium, Advanced and Enterprise**—but does **not publish currency-denominated prices**. Each plan is **quote-based/contact sales**, so no monthly or annual list price can responsibly be reported and private contract estimates are excluded. The page does not state whether contracts are month-to-month or annual, nor does it state annual-discount terms. This is current official pricing information as publicly available on 6 October 2026.

All three tiers advertise unlimited users, all test types, and unlimited test-case creation. Premium includes **5,000 credits/month**, Advanced **20,000 credits/month**, and Enterprise **40,000 credits/month**. Enterprise additionally lists testing private environments. Mobile parallel testing is an available add-on on all tiers [7] (**official pricing page**). Web parallelism is listed as 3 included on Premium, 4 on Advanced and 5 on Enterprise; public/private mobile parallelism is shown as add-on rather than included [7].

The metering unit is a **test-run credit**, not user, workspace, minute, or browser-minute pricing. The official usage guide states: one Web test run = 1 credit; one standalone API test run = 0.1 credit; one native Mobile test run = 5 credits, with mobile available to Premium and Enterprise customers [9]. A web run containing API steps remains 1 credit; only standalone API tests use 0.1 credit [9]. The pricing page says a test run on a tablet/mobile browser profile is still a Web test and costs 1 credit [7]. The usage guide says AI usage is unlimited at no additional cost under the credits change [9].

The public pricing page does not disclose the price of add-on credits, an overage rate, a hard overage policy, currency, minimum commitment, annual-vs-monthly billing, or whether unused credits roll over. “Add-on Credits Available” appears as a comparison heading without published values [7]. These are material commercial unknowns; do not infer them from the old plan names or third-party reviews. TestGuild’s page calls Reflect paid and “custom quote” [3], but its generic pricing summary is less precise than SmartBear’s current page and should not substitute for the official terms. Older pre-acquisition or pre-credits prices are intentionally not reproduced because no public price is needed to resolve the current pricing question and historical web snippets are contradictory.

## 4. Authoring, oracle, modules, diagnostics, privacy, portability, and governance

**Recorder and intent authoring — documented.** Reflect records actions in an interactive cloud browser and also accepts free-form AI Prompt Steps [1][4]. A prompt can be edited into an action, Boolean assertion, or question. AI Prompt Steps do not currently support file upload/download, drag-and-drop/swipes, text highlighting, or native browser alerts/prompts [4] (**documented limitations**). Recorded steps retain selectors and editable descriptions; AI fallback is invoked if original selectors fail [4].

**Assertions and semantic contracts — documented assertions, unverified semantic layer.** Exact, formula, range, list, non-empty, variable and AI Boolean assertions are documented [4][5]. This is a substantial test-oracle capability. There is no public evidence that Reflect models business intent, typed domain inputs/outputs, state transitions, dependencies, risk, approved rules, BLOCKED status semantics, or human approval of generated business contracts. AI-generated actions/assertions are user-editable, but I found no public workflow proving mandatory human approval before a self-healing repair is accepted (**unverified**).

**Reusable modules and datasets — documented.** Segments and Parameters support reusable login/search/workflow blocks, and Variables support extracted values and generated data [5][6]. Segment nesting is explicitly unsupported [6]. The public docs do not describe a catalog of semantic business modules, module versioning with compatibility contracts, or cross-application domain primitives (**unverified**).

**Self-healing and governance — documented mechanism; governance depth unknown.** Reflect’s AI Assistant uses expected text and step descriptions to locate an element after selector failure [4]. The public description calls this self-healing, but does not quantify repair precision/recall, show a repair diff/audit trail, or explain policy controls to approve/reject a proposed repair. Therefore self-healing is documented; safe human-governed healing is **unverified**.

**Diagnostics/evidence — documented.** HD run video, synchronized steps, network logs and JavaScript console logs are included in every run according to SmartBear’s product and pricing pages [1][7]. The product page also markets comprehensive repro steps. Whether screenshots, DOM snapshots, HAR files, immutable evidence hashes, or exportable evidence bundles are available is not established by the reviewed public sources (**unverified**).

**Local execution, cloud AI and privacy — important distinction.** Reflect is fundamentally cloud-executed: its local-testing documentation says local apps can be exposed through ngrok to record and run cloud tests [10]. For private environments, SmartBear offers a Reflect Tunnel via an encrypted tunnel (the pricing page lists private environments at Enterprise) [7]. This is not an offline/local-first architecture. Reflect’s LLM documentation says it uses OpenAI, Google Gemini and Anthropic, with model routing handled internally and prompt data sent to the selected provider; model selection is not user-configurable unless documented [11] (**documented capability/architecture**). The docs say handling follows SmartBear security and privacy standards, but do not establish offline AI, customer-controlled model hosting, no-retention guarantees, or that sensitive page content never leaves the customer environment (**unverified**).

**Portability and lock-in — partial public evidence.** Reflect exposes a Developer API for tests, suites and segments and an API-based execution path [8][4], which provides integration portability. The reviewed docs do not describe a full export to Playwright/Selenium/Gherkin, an open test-file format, or local replay of exported tests. Tests therefore appear operationally portable through API integrations but potentially definition- and execution-cloud-dependent (**assessment/inference**). SmartBear ownership and integration into its broader hub ecosystem can increase switching costs, though no exclusive interoperability is established.

## 5. Plausible moat mechanisms and grade

**Accumulated learned artifacts — emerging, with high uncertainty.** Reflect can accumulate a customer’s step descriptions, selectors, expected text, Segments, Parameters, run history and perhaps repair context. Those artifacts can improve resilience and make migration costly (**assessment based on documented storage/reuse mechanisms**). Public documentation does not confirm that customer data trains a shared model, that repairs improve across accounts, or that the accumulated corpus is materially proprietary. Grade: **emerging/unproven**.

**Workflow and suite switching costs — moderate.** Reusable Segments propagate changes to dependent tests, Parameters feed modules, secrets and suites encode operational knowledge, and CI integrations trigger remote execution [5][6][8]. Rebuilding these assets elsewhere costs time and creates migration risk. Grade: **moderate**, because the lock-in is practical but APIs and a mature no-code category limit exclusivity.

**Distribution and ecosystem — moderate.** SmartBear owns established brands and states Reflect is integrated into a larger hub strategy [2]. Its broad CI/CD, issue/test-management and API integrations can lower adoption friction [1][8]. This is distribution and operating capability, not a product moat by itself. Grade: **moderate**, with uncertainty about Reflect-specific adoption and retention.

**Proprietary infrastructure/operating capability — moderate.** Running interactive cloud browsers, cross-browser/device execution, private tunnels, AI routing, video, network/console capture and usage metering is operationally nontrivial [1][7][9][10][11]. Competitors can build similar infrastructure, and public evidence does not disclose scale, reliability, or unique algorithms. Grade: **moderate** for execution capability, not strong defensibility.

**AI feature count and generic model access — not a moat.** Natural-language prompts, self-healing claims, and multi-provider LLM access are distinctive product features but are reproducible by well-funded competitors. SmartBear’s acquisition is a distribution/resource advantage, not proof of a durable moat. Overall moat grade: **moderate but not proven**; strongest mechanisms are workflow switching costs, ecosystem distribution, and operational execution, while a durable learned-artifact network effect is unverified.

## 6. Supported limitations, inference, and Veyra fit/risk

Supported limitations include: quote-only pricing with no public currency or overage terms [7]; AI prompt steps not supporting uploads/downloads, drag-and-drop/swipes, highlighting or native alerts [4]; Segments cannot nest [6]; local testing requires exposing a local application through ngrok rather than running the whole system locally [10]; AI model routing is internal and not user-configurable by default [11]; and the product is cloud-oriented with remote CI/API execution [8]. TestGuild independently reports limited advanced scripting/custom logic and no desktop automation [3], but this is catalog commentary, not an official capability matrix.

The major Veyra opportunity is not “no-code browser testing” alone: Reflect already covers recorder + natural language + assertions + reusable parameterized segments + evidence + AI resilience, and it exceeds Veyra V0 in API, mobile, cross-browser, CI/CD, scheduling and cloud scale [1][7]. Veyra could differentiate by making local-first execution and privacy the default, treating AI as human-governed suggestions rather than opaque runtime decisions, and centering explicit business intent, semantic modules, approved rules, state/dependency context, risk, and evidence-backed PASS/FAIL/BLOCKED. These are strategic inferences, not proof of unmet market demand.

Reflect’s pricing and cloud architecture create a plausible gap for small/manual testers who need predictable low-volume economics, offline or private execution, and ownership of test artifacts. However, Reflect’s unlimited-user tiers and free trial reduce seat-based friction, while credits make execution economics visible but potentially hard to forecast. Veyra must validate whether target customers actually reject cloud AI/remote execution, whether browser-local execution can support trustworthy evidence and AI assistance without a service, and whether semantic ABM artifacts are valuable enough to offset Reflect’s breadth. Do not assume Reflect lacks any feature solely because it was not found in public docs.

## 7. Material evidence gaps

Public sources do not reveal list prices, currency, monthly versus annual billing, overage/add-on-credit rates, retention/rollover, minimum commitments, or contract length. They do not provide independent benchmark data for healing accuracy, flake reduction, run reliability, AI assertion correctness, execution latency, or coverage. They do not establish full test-definition export, offline mode, exact evidence retention/immutability, model-data retention/training policy, repair approval/audit controls, historical defect memory, risk/coverage graphing, or business-semantic contracts. A hands-on benchmark would require signup/trial and was not performed per task constraints.
