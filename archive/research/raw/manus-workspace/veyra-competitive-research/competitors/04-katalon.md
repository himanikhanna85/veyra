# Katalon

**Research date: 6 October 2026.** This profile covers Katalon as one competitor. Claims are labelled by evidence status: **documented capability** means Katalon’s public documentation describes an implementation; **vendor-marketed** means a positioning or quantified claim on a Katalon marketing page; **independently supported** means a non-Katalon source; **assessment/inference** is my competitive interpretation, not a benchmark. A public page is not a hands-on benchmark.

## Active product identity and intended customer

Katalon’s current identity is **Katalon True Platform**, described as a broad software quality-management/AI testing platform. Its principal local authoring product is **Katalon Studio**, an IDE built on Selenium for web UI, API, mobile and desktop tests. The current platform also separates test planning/management and analytics, local execution, and cloud execution. Katalon’s own platform page describes a Plan and Organize layer (TestOps, now rebranded True Platform), Author (Studio), Execute (Test Execution–Local and Test Execution–Cloud), and Analyze (True Platform analytics) [1]. This is **vendor-marketed**, although the linked product documentation confirms the product boundaries.

The 2026 naming transition matters. Studio 11.1.0 renamed Katalon TestOps to **Katalon True Platform**, Katalon Runtime Engine to **Katalon Test Execution - Local**, and Katalon TestCloud to **Katalon Test Execution - Cloud**, while rebranding StudioAssist as Katalon AI Assistant [2]. Older articles, contracts, URLs and search results therefore use TestOps, Runtime Engine and TestCloud. Studio 11.5.0 was documented as the latest release on 27 August 2026 [2].

The intended customer is a QA organization that wants low-code authoring plus script/full-code escape hatches and a centralized, multi-application quality operation. The pricing page targets “individuals or small automation teams” for Professional and larger teams needing SSO, deployment, compliance and control for Enterprise [3]. Its product page claims 30,000+ quality teams and named enterprise customers; those are **vendor-marketed**, not independently verified adoption evidence [1][3]. It is materially broader than Veyra’s proposed manual/low-code browser QA loop: Katalon explicitly includes API, mobile, Windows desktop, CI/CD, cloud devices, scheduling, parallel execution and TestOps-style analytics.

## Distinctive capabilities and mechanism versus a low-code category baseline

Studio combines Recorder and Spy interactions with a manual view and script editor. Katalon documents creating tests by interacting with the application, then switching between manual and script interfaces; built-in and custom reusable keywords provide a higher-level action library [4]. The baseline category has record/playback and assertions; Katalon’s distinction is the breadth of one project/execution flow across web UI, API, mobile and desktop, plus a single project model with object repository, keywords, profiles, test cases and suites. The cross-application claim is **documented capability**, not a claim that every heterogeneous workflow works without customization.

Its “module” mechanism is principally technical test reuse rather than a business-semantic contract. Reusable test artifacts, built-in keywords, custom keywords, test objects and object repositories let teams factor actions and locators. Test suites and suite collections group cases; dynamic suites can add cases through a search query. Data-driven testing binds test variables to external or generated data. These are **documented/vendor-described capabilities** [1][4]. I did not find public documentation establishing Veyra-like reusable semantic business modules whose contract explicitly records business intent, accepted inputs/outputs, approved rules, state transitions, dependencies and risk. That absence is an unverified dimension, not proof the product cannot model business concepts through custom keywords or metadata.

Katalon has explicit test verification keywords and AI-assisted assertion keywords in Studio 11.5.0: “Ask”, “Assert File” and “Assert Text” can send a prompt/attachment to an AI model and perform AI-assisted validation [2]. Conventional verify/assert keywords and failure handling are also part of the documented Studio model. This is a stronger executable oracle story than mere recorder playback, but its public material does not show a durable business-rule/semantic assertion graph comparable to an ABM. The latter is an **assessment**.

Self-healing is a concrete, governed locator-repair mechanism rather than an autonomous business-level repair system. When the original locator fails, classic self-healing tries other known locators; AI self-healing can inspect page source, accessibility tree, full-page screenshot and element screenshots to suggest an alternative [5]. A suggestion appears in Self-healing Insights with the broken locator, proposed locator, recovery method and screenshot; the user may approve or discard it. Project settings let teams enable/disable the feature, prioritize locator methods, exclude keywords and override selection per object [5]. Importantly, Katalon warns that applying self-healing to Verify/Wait keywords can cause false positives and recommends restricting it to interactions [5]. This is **documented capability** and a meaningful example of human governance, but it preserves an element locator; it does not claim to infer or preserve business intent.

Execution evidence is detailed but oriented to automation debugging. The Log Viewer supports real-time step logs, tree structure, configurable log levels, and execution progress information; API/web-service runs can produce HAR files and cURL commands [6]. Studio 11.5.0 adds redesigned PDF reports with error summaries, retries, listeners/hooks, comments and AI-generated failure analysis, plus automatic failure screenshots for Windows tests [2]. These are **documented capabilities**. They support evidence-backed outcomes, but public documentation does not establish that Katalon’s outcome model natively distinguishes Veyra’s evidence-first PASS/FAIL/BLOCKED semantics with a mandatory human-readable reason for each result.

Katalon has historical analytics and quality-management concepts beyond a local test runner: platform pages describe tagging, mapping test data, smart/dynamic suites, scheduling, execution analytics and organization-wide visibility [1]. The public materials reviewed do not establish a durable historical “defect memory” that stores business-level failure patterns and approved rules as a portable model. The independent Qameta article, published January 2023, describes Katalon features including coverage, release, flakiness, pass/fail trend reports and finding similar failures from previous execution results, but this is old and third-party content, so it should not override the current official product documentation [7]. Treat the presence of analytics as **documented/vendor-described**, and a learned ABM-like memory as **unverified**.

## Current pricing, free/trial status and execution add-ons

Pricing was checked on 6 October 2026 and is time-sensitive. The current official public offer shows **Katalon Studio Professional at USD $1,000 per seat per year** for the first three seats on the first online purchase, billed annually, shown as approximately $84/seat/month. The page labels the crossed-out $2,199 figure and the discount as a limited-time first-purchase offer ending 31 October; therefore $1,000 is not a general perpetual list price and the $84 number is not a true monthly subscription [3]. Professional includes local authoring, recording, playback and execution, web/mobile/API/desktop testing, data-driven testing, unlimited/dynamic suites, parallel execution and integrations. It includes AI test authoring/failure analysis/self-healing and unlimited AI sessions according to the same page [3]. Currency is USD; the page does not state per-run, per-test, per-minute or overage charges for the Studio seat.

**Free Studio** is advertised as author/run locally with record/playback and local execution, and the page links a 30-day free trial with no credit card required [3]. The comparison says Free excludes desktop testing, parallel execution and AI self-healing/failure analysis, while it includes basic web/mobile recording, local execution, basic data sources, up to 40 static dynamic-suite cases, Git-based source control and report export/share [3]. Because the page’s headline says “Free” while the CTA is “Start 30-day free trial,” distinguish a free local tier from trial mechanics; the page does not state a numeric free-run quota in the material captured.

**Enterprise Studio/True Platform is quote-based**: annual contract, tailored to seats, deployment and compliance. It adds SSO/SAML and SCIM, RBAC/audit logs, private cloud or on-premises deployment, centralized license/usage management, hybrid licensing convertible to offline licenses, security/custom terms, SLA support and onboarding [3]. No public enterprise price, per-user minimum, usage overage or quota was found; do not estimate it.

Katalon separates cloud execution from Studio. The official Test Execution–Cloud comparison says the trial provides **3 cloud sessions for Desktop Browser Testing for 30 days** from organization creation, with unlimited testing minutes. The paid **per-session** plan is monthly or annual; a session is a purchased concurrency unit, and one session runs one sequence for as long as needed. Purchased session count is the maximum number of parallel tests. Automation and Live environments share the same session pool [8]. Session types include Desktop Browser, Desktop and Mobile Browser, Mobile Native App, Live Testing and Private Device Testing, with OS coverage Windows/Linux/Android/iOS and Chrome/Firefox/Edge in the comparison [8]. The comparison does not publish USD prices, overages, or a simple per-minute rate. The cloud add-on is therefore **quote/checkout-dependent**, with pricing unit documented as session/concurrency rather than minutes.

The Studio pricing page says cloud execution “requires TestCloud add-ons” (now Test Execution–Cloud), while headless/CI execution requires Katalon Runtime Engine add-ons (now Test Execution–Local) [3]. The page claims Professional includes parallel execution, but that should not be read as including unlimited cloud device capacity: the cloud product separately meters purchased sessions. The page also says CI/CD command-line execution requires the Runtime Engine add-on [3]. Current public materials do not clearly expose Runtime Engine/Test Execution–Local price, number of concurrent local nodes, minute quota, or overage terms. Treat those dimensions as sales/checkout-only and unverified.

A January 2023 independent Qameta article reported a former Free plan with 2,000 monthly test results, five platform users, one organization, three active projects and six-month retention; Premium at $25/month or $299 annually, 3,500 monthly results; and an Ultimate plan with 30,000 results and quote pricing [7]. These figures materially contradict the current 2026 Studio/True Platform page and are retained only as dated historical evidence, not current pricing. Likewise, older third-party pricing articles and reviews should not be used as current list prices. No public source reviewed established current per-test, per-execution-minute or overage pricing for Studio or cloud sessions.

## Local execution, AI processing, governance and portability

Studio supports local authoring, recording and local execution; the free and Professional plans explicitly say so [3]. Local browser execution is not equivalent to offline/private AI. AI self-healing can use Katalon’s configured AI model or a user-supplied model/API key; the documentation describes LLM analysis of DOM/page source, accessibility tree and screenshots and warns that supplying an OpenAI key through launch arguments can expose it [5]. Enterprise advertises offline/air-gapped activation, private cloud/on-premises deployment and bring-your-own AI provider [3]. These are **documented/vendor claims**, but the reviewed material does not establish that all AI processing can run offline or that a default cloud model never receives test data. A Veyra privacy comparison must therefore ask where screenshots, DOM, logs and prompts go, what retention applies, and which model endpoint is used.

Governance is comparatively explicit for self-healing: enablement, data-source choice, locator prioritization, excluded verification keywords, per-object overrides, and approve/discard actions are documented [5]. Studio 11.1 adds command-line flags to enable/disable AI self-healing and choose input sources [2]. This is a good control pattern for Veyra’s human-governed AI suggestions, although Katalon’s control is locator-centric. Public documentation reviewed did not establish a complete organization-wide approval ledger for AI-generated assertions, business rules, or semantic module changes.

Katalon projects use a Selenium-derived and Katalon-specific artifact model, with scripts, test objects, keywords and repository files that can be managed in Git; Studio can import Selenium projects and integrates with Git providers [1][3]. This gives practical source-control portability and a migration path for Selenium users. It is not the same as exporting a clean, vendor-neutral semantic test model: Katalon keywords, object repository conventions, profiles and proprietary execution/reporting integrations create switching costs. Public evidence did not establish a one-click export to a Veyra-like ABM or a fully independent runner.

## Moat mechanisms and defensibility

**Emerging-to-moderate: accumulated test artifacts and organizational switching costs.** A customer that stores many test cases, object repositories, custom keywords, data profiles, integrations, suites, reports and approved locator repairs in Katalon has migration work and regression risk. The self-healing Insights workflow can accumulate approved locators, and AI Assistant project memory is now documented as retaining user preferences/project conventions across conversations and sessions [2][5]. This is a plausible artifact/data moat, but it is not yet evidence of a proprietary cross-customer learned model; public documentation does not show the scale, uniqueness or transferability of that learning. Grade: **emerging**, uncertainty high.

**Moderate: workflow/distribution and ecosystem.** Katalon bundles a local IDE, cloud execution, local/CI execution, management/analytics, integrations, training/community and enterprise controls. The platform claims broad adoption and named enterprise users [1][3], but those are vendor-marketed. Integration into Jira/ALM, Git, CI/CD, Slack/Teams, Selenium migration and enterprise identity can make Katalon part of a team’s operating process. Grade: **moderate**, because breadth and distribution can protect an incumbent, though feature breadth alone is not a moat and adoption figures were not independently verified here.

**Moderate: proprietary operating infrastructure for cloud execution.** Test Execution–Cloud supplies browser/device environments, parallel-session capacity, live testing and private devices; managing those environments, drivers, device inventory and reliability is operationally difficult [8]. This is a plausible infrastructure moat against a small local-first product, but Katalon’s public pages do not disclose reliability, fleet economics or comparative performance. Grade: **moderate**, with execution-quality uncertainty.

**Unproven: AI and self-healing as a durable technical moat.** Katalon has concrete signals, data-source controls and approval UX, but locator fallback plus an LLM is replicable by competitors and does not by itself encode business semantics. No evidence reviewed demonstrates a uniquely proprietary model, exclusive data, superior healing precision, or a persistent approved-rule graph. Grade: **unproven**. Generic LLM access and feature count are not treated as moats.

**Emerging: enterprise trust/deployment capability.** SSO/SCIM, audit logs, private cloud/on-prem, offline activation, hybrid licensing and support/SLA are commercially meaningful for regulated or air-gapped teams [3]. These can raise procurement and switching barriers, but they are capabilities rather than exclusive IP. Grade: **emerging-to-moderate**.

## Limitations, supported versus inferred, and fit/risk for Veyra

Katalon’s documented scope is much broader and heavier than Veyra’s V0. Its Professional plan includes web, mobile, API and desktop; cloud execution is a separate add-on with session concurrency; CI/CD, scheduling, parallelization and multi-browser/device testing are central parts of the platform [1][3][8]. This supports a fit-risk inference: Katalon may be overpowered, more expensive and operationally complex for a manual/low-code tester who needs a local-first browser loop and fast evidence, but that is not a hands-on usability benchmark.

Katalon’s object/locator abstraction is not publicly shown to be a business-semantic contract. Its assertions verify elements, text, attributes, files or AI responses; its reusable keywords are technical or project-defined. Therefore Veyra can differentiate around business-language modules with explicit inputs/outputs, preconditions, postconditions, approved rules, dependencies, state and risk. This is an **opportunity assessment**, not proof that Katalon cannot implement it with custom keywords and metadata.

Katalon’s self-healing is governed but primarily aimed at keeping UI automation running. Katalon itself warns that healing verification/wait keywords may create false positives [5]. Veyra’s strongest opportunity is to make “suggestion did not silently change the oracle” a first-class principle: show before/after evidence, require explicit approval, preserve blocked status when the target cannot be safely identified, and separate locator repair from assertion/rule repair. Katalon’s approval workflow validates the feasibility of this governance pattern, but does not prove a gap in all of Katalon’s editions.

Katalon provides logs, screenshots, reports and failure analysis, but public material does not establish a mandatory evidence-backed PASS/FAIL/BLOCKED result contract with human-readable rationale. A Veyra product should win on the reliability and legibility of manual QA evidence, not merely on “AI” or record/playback. It should also preserve local privacy by making endpoint, retention and redaction explicit; local browser execution must not be advertised as offline/private AI without proof.

Katalon’s portability is mixed: Selenium import and Git support are positives, while Katalon-specific keywords, repositories, execution add-ons, cloud sessions and reporting create lock-in. Veyra should make its semantic modules and evidence exportable in open formats, preserve raw screenshots/DOM/action traces, and allow a local runner without paid cloud concurrency. Conversely, Katalon’s scale, API/mobile/desktop coverage, CI and enterprise controls are areas Veyra intentionally excludes in V0 and should not claim to match.

## Material evidence gaps and limitations of this research

The official pricing page is dynamic and promotion-led; it exposes current Studio seat pricing but not public prices for Enterprise, Test Execution–Local, Test Execution–Cloud sessions, AI provider usage, overages, or concurrency beyond the cloud session definition. Those are explicitly quote/checkout-dependent; no private contract estimate is made. The cloud documentation states unlimited minutes per purchased session, but does not mean unlimited sessions or unlimited devices [8].

Several direct documentation URLs for recorder, test objects, data-driven testing and project settings returned no extractable content through the text fetcher, so those dimensions were not overstated. Capabilities cited from the overview/pricing pages and release notes are documented, while any conclusion about absent semantic contracts, offline AI, defect memory, or export limitations remains “not publicly established,” not a claimed feature absence. No signup, trial, hands-on benchmark, purchase, product execution or interactive browser session was used.
